# Remote State Backend Configuration

## Overview
The AI/ML Landing Zone now automatically manages Terraform remote state using Azure Storage with Entra ID (RBAC) authentication only.

## How It Works

### Automatic Setup
When you run `azd provision`, the `ensure-remote-state.sh` script automatically:
1. ✅ Checks if remote state backend exists
2. ✅ Creates storage account if needed (RBAC-only, no shared keys)
3. ✅ Configures Terraform backend in `main.tf`
4. ✅ Assigns Storage Blob Data Contributor role to your user
5. ✅ Is idempotent - safe to run multiple times

### State Storage Details
- **Resource Group**: `tfstate-rg-aiml-lz`
- **Storage Account**: Auto-generated (e.g., `tfstate2857dabb`)
- **Container**: `tfstate`
- **State File**: `aiml-lz-default.tfstate`
- **Authentication**: Entra ID (RBAC) only
- **Location**: Matches `AZURE_LOCATION` environment variable

### Backend Configuration
The script creates a dynamic backend configuration file at `examples/default/backend.tfvars`:
```hcl
# Auto-generated by ensure-remote-state.sh
resource_group_name  = "tfstate-rg-aiml-lz"
storage_account_name = "tfstate<unique>"
container_name       = "tfstate"
key                  = "aiml-lz-default.tfstate"
use_azuread_auth     = true
```

The `main.tf` contains only an empty backend block:
```hcl
terraform {
  # Backend configuration is managed by ensure-remote-state.sh
  backend "azurerm" {}
}
```

This approach:
- ✅ Avoids hardcoding storage account names
- ✅ Allows different storage accounts per environment
- ✅ Auto-generates configuration on each deployment
- ✅ File is ignored by git (regenerated each time)

## Usage

### Initial Deployment
```bash
azd provision
```
The remote state backend is automatically created and configured.

### Subsequent Deployments
```bash
azd provision
```
The script detects the existing backend and reuses it.

### Manual Backend Setup
```bash
./examples/scripts/ensure-remote-state.sh
```

### Cleanup
```bash
azd down
```
**Note**: The state storage (`tfstate-rg-aiml-lz`) is **NOT** deleted to preserve state history.

To manually delete state storage:
```bash
az group delete --name tfstate-rg-aiml-lz --yes
```

## Key Features

### ✅ Policy Compliant
- **No shared access keys** - Uses Entra ID (Azure AD) authentication only
- Complies with `allowSharedKeyAccess = false` policies
- RBAC-based access control

### ✅ Idempotent
- Safe to run multiple times
- Won't recreate existing resources
- Automatically updates configuration if needed

### ✅ Team Ready
- State is stored in Azure Storage
- Accessible to all team members with proper RBAC permissions
- Prevents state file conflicts

### ✅ State Preservation
- State storage is NOT deleted on `azd down`
- Preserves deployment history for recovery
- Minimal cost (~$1/month)

## Troubleshooting

### RBAC Permission Issues
If you see 403 errors, wait 30-60 seconds for RBAC propagation:
```bash
# Check role assignment
az role assignment list \
  --scope "/subscriptions/<sub-id>/resourceGroups/tfstate-rg-aiml-lz/providers/Microsoft.Storage/storageAccounts/<storage-name>" \
  --query "[?roleDefinitionName=='Storage Blob Data Contributor'].principalId" -o tsv
```

### Backend Already Configured
If the backend is already configured with a different storage account, the script will update it to match the existing storage.

### Manual State Migration
If you need to migrate existing local state to remote backend:
```bash
# Ensure backend is configured
./examples/scripts/ensure-remote-state.sh

# Copy your state file
cp terraform.tfstate.backup terraform.tfstate

# Initialize with migration
terraform init -migrate-state
```

## Architecture

```
┌─────────────────────────────────────┐
│         azd provision               │
└──────────────┬──────────────────────┘
               │
               ├─► check-prerequisites.sh
               │   (Verify Azure providers)
               │
               ├─► ensure-remote-state.sh
               │   ├─► Check if backend exists
               │   ├─► Create storage if needed
               │   ├─► Assign RBAC permissions
               │   └─► Update main.tf config
               │
               ├─► terraform init
               │   (Uses remote backend)
               │
               └─► terraform apply
                   (State stored in Azure)
```

## Security Considerations

- **Authentication**: Entra ID (RBAC) only
- **Encryption**: Blob encryption enabled by default
- **Public Access**: Disabled (`allowBlobPublicAccess = false`)
- **Shared Keys**: Disabled (`allowSharedKeyAccess = false`)
- **Network**: Default allows Azure services (can be restricted further)
